## 2. ผู้ดูแลว่าง / เวลาชน

| TC | เคส | ผล | หลักฐาน |
|---|---|---|---|
| _05 | ช่วงที่ผู้ดูแลไม่เปิดรับ / คร่อม 2 slot | PASS | เปิดแค่ morning: 13:00–15:00 → 409 "ผู้ดูแลไม่ได้เปิดรับงานในช่วงเวลานี้" · 11:00–14:00 → 409 · เปิด morning + afternoon: 11:00–14:00 → 201 |
| _06 | ซ้อนกับใบเดิมที่ `pending` / `accepted` / `confirmed` | PASS 3/3 | ผู้จองคนเดิม 09:00–11:00 แล้วจอง 10:30–12:00 → 409 · ต่อกันพอดี 11:00–12:00 → 201 |
| **_X1** | **ผู้ดูแลคนเดียว ผู้จองคนละคน เวลาซ้อน** | **FAIL** | ใบแรก 09:00–12:00 (accepted) → ผู้จองอีกคนจอง 10:00–11:00 กับผู้ดูแลคนเดิม → **201** และผู้ดูแล **กดรับได้** (accepted) = มีงานที่ต้องไปพร้อมกัน 2 งาน |

**_X1 รายละเอียด:** เช็คเวลาชน (`booking.service.ts` "ตรวจสอบ time conflict") ตีกรอบที่ **ผู้รับบริการ / ผู้จอง** เท่านั้น (PYG-424) ส่วนฝั่งผู้ดูแล PYG-524 เช็คแค่ตารางว่างรายสัปดาห์ (`caregiver_availability`) ไม่ได้ดูใบจองที่มีอยู่ และ `acceptBooking` ก็ไม่เช็ค
- prod (อ่านอย่างเดียว 2026-10-03): คู่ใบจองของผู้ดูแลคนเดียวกันที่เวลาซ้อนและยังไม่ปิด **5 คู่** (รับแล้วทั้งสองใบ 4 คู่) — ทั้งหมดเป็นวันในอดีต ไม่มีคู่ที่กำลังจะถึง
- การ์ดเขียน "ซ้อนกับใบที่ pending/accepted/confirmed → ไม่ได้" ใต้หัวข้อ "ผู้ดูแลว่าง" — ถ้าเจตนาคือฝั่งผู้ดูแลด้วย ข้อนี้ยังไม่ผ่าน
- ข้อเสนอ (ยังไม่แก้): ตอนสร้างใบจองที่ระบุผู้ดูแล + ตอน `acceptBooking` เช็คใบของผู้ดูแลคนนั้นในวันเดียวกันที่ `accepted`/`confirmed`/`in_progress` (ตอนสร้างควรนับ `pending` ด้วยหรือไม่ = ต้องตัดสินใจ เพราะผู้ดูแลอาจปฏิเสธใบใดใบหนึ่ง) · ต้องกันแข่งกันด้วย (lock แถวผู้ดูแล) ไม่งั้นสองคนกดพร้อมกันก็หลุด
